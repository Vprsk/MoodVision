# EmoSense — десктопное приложение (PySide6)

GUI для мультимодального распознавания эмоций поверх контракта
`contracts.BaseFaceEmotionModel`. Обслуживает FER-модель, принимает
видеопотоки (RTSP/HTTP, файл, веб-камера), выводит живое видео с
разметкой, обрабатывает **много потоков параллельно** и позволяет
**выбирать пресет** обработки (пайплайн + параметры).

## Запуск

Из корня проекта (чтобы корректно разрешались импорты `contracts`/`models`):

```bash
# Windows
env\Scripts\python app\main.py
# Linux/macOS
env/bin/python app/main.py
```

На HEADLESS-машине (без дисплея) для проверки запуска:

```bash
QT_QPA_PLATFORM=offscreen env/Scripts/python app/main.py
```

End-to-end проверка видеоворкера с реальной моделью на `data/test.mp4`:

```bash
env/Scripts/python mood_base/scripts/e2e_check.py
```

### Ключевые решения

- **Контракт-центричность.** GUI работает только с `FrameResult` из
  `contracts/` и не знает о конкретных моделях. Любая реализация
  `BaseFaceEmotionModel` подключается без правок UI.
- **Многопоток.** Каждый видеопоток = отдельный `QThread` (`VideoWorker`) со
  **своим экземпляром модели** (YOLO+ByteTrack содержат состояние треков и не
  потокобезопасны). Кадры идут из воркера в GUI через Qt-сигналы.
- **Выбор пайплайна.** `pipeline_registry.register_pipeline()` добавляет новую
  реализацию контракта — она сразу появляется во вкладке «Пресеты» (встроенный
  пресет создаётся автоматически).
- **Кэш HF-модели.** ViT-классификатор эмоций (`trpakov/vit-face-expression`)
  загружается один раз на процесс и переиспользуется всеми экземплярами
  пайплайна (старт нового потока не перечитывает модель). Сначала берётся
  локальный кэш HuggingFace, сеть используется только при первой загрузке —
  см. `mood_base/models/current_yolo_vit.py`, проверка
  `mood_base/scripts/emotion_cache_check.py`.
- **Корректное завершение.** `MainWindow.closeEvent` останавливает все воркеры.

## Добавление нового пайплайна

1. Реализуйте контракт (пример — `mood_base/models/current_yolo_vit.py`):

   ```python
   from contracts.base import BaseFaceEmotionModel
   from contracts.schemas import FrameResult

   class MyPipeline(BaseFaceEmotionModel):
       def __init__(self, model_path: str) -> None: ...
       def predict(self, frame_id: int, frame) -> FrameResult: ...
   ```

2. Зарегистрируйте в `app/core/pipeline_registry.py` (в `_register_builtin_pipelines`):

   ```python
   def _my_factory(**params): return MyPipeline(**params)
   register_pipeline(PipelineInfo(key="my", label="Мой пайплайн",
                                  factory=_my_factory, defaults={...}))
   ```

Готово — пайплайн доступен в UI.

## Источники видеопотоков

В поле «Источник» диалога добавления потока:
- `rtsp://...` / `http://...` — IP/сетевая камера;
- `C:/path/video.mp4` — видеофайл;
- `webcam:0` (или просто `0`) — локальная веб-камера по индексу.

## Плеер (страница «Потоки»)

Под видео — панель управления воспроизведением:
- **Play / Pause** — пауза и возобновление показа (кадры перестают читаться);
- **⏪ / ⏩** — перемотка на ±10 секунд;
- **прогресс-бар** — позиция + таймкоды `MM:SS`; можно тащить ползунок для
  перехода к нужному моменту.

Перемотка и прогресс-бар доступны **только для видеофайлов**. Для прямых
эфиров (RTSP/HTTP) и веб-камеры перемотка невозможна — элементы управления
автоматически отключаются, а вместо длительности показывается `LIVE`.

Реализация: `VideoWorker` управляет `cv2.VideoCapture` (пауза/seek через
`CAP_PROP_POS_*`) в своём потоке; виджет `VideoPlayer` эмитит намерения
(play/seek), которые `StreamsPage` связывает с активным воркером.

## Статусы клиентов

`classify_status()` сводит эмоцию+уверенность к статусу:
- негатив + высокая уверенность → **Инцидент**;
- низкая уверенность / unknown → **Не уверена**;
- иначе → **Норма**.

## Группы потоков

Потоки можно организовывать в **группы** (например, по локациям/офисам).

- **Свернуть/развернуть группу** — клик по её заголовку (стрелка ▾/▸).
- **Контекстное меню группы** (правый клик по заголовку):
  - «Добавить поток в группу»;
  - «Переименовать группу» (потоки переезжают автоматически);
  - «Удалить группу» (потоки переносятся в «Без группы»).
- **Меню потока** (правый клик по камере или кнопка «⋯» на карточке):
  - «Переместить в группу» → выбор из существующих (текущая группа
    отмечена ✓) или «Новая группа…» с вводом имени;
  - «Переименовать поток»;
  - «Удалить поток» (с подтверждением; удаляется из списка и сохранения).

При добавлении потока группа выбирается из списка (или вводится новая).
Список групп, их порядок и свёрнутое состояние сохраняются в `groups.json`.

## Пресеты обработки

**Пресет** — именованный набор «пайплайн + параметры». Выбирается при
добавлении потока, чтобы не настраивать пороги/частоту каждый раз.

- **Встроенные пресеты** — по одному на каждый зарегистрированный пайплайн,
  с параметрами по умолчанию из реестра; доступны только для просмотра.
- **Кастомные пресеты** — создаются во вкладке «Пресеты»: имя, выбор
  пайплайна и параметры (поля генерируются по типам default: `bool` →
  список Да/Нет, `int`/`float` → спинбокс, строка → текстовое поле).
  Можно изменить и удалить; сохраняются в `presets.json`.

Вкладка «Пресеты»: слева — список, справа — пайплайн, описание и таблица
параметров выбранного пресета. Диалог добавления потока берёт пресет из
`PresetManager.resolve()` и прописывает `pipeline_key` + `pipeline_params`
в `StreamConfig` (при отсутствии пресета — откат к дефолту пайплайна).
